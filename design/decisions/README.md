# Decisions 入口

## 定位

`design/decisions/` 记录重要设计取舍，解释为什么当前契约长成这样。它不是开发日记，也不是替代当前 design 的真理来源。

## 准入

只记录满足至少一项的决策：

- 改变跨模块边界、公开接口、持久化结构或核心流程。
- 在多个可行方案之间做了长期取舍。
- 未来维护者很可能重新提出已被否决的方案。
- 决策代价明显，需要说明何时可以推翻。

## 条目要求

每条 decision 应短而稳定，并包含：

- 背景：当时需要解决的稳定问题。
- 方案：选中的契约或边界。
- 取舍：放弃了什么，承担了什么成本。
- 状态：`Active`、`Superseded` 或 `Replaced by ...`。
- 关联：指向当前 design、tests 或 regression。

## 维护

- 能沉淀为当前契约的内容，写回对应 design。
- 已失效的 decision 应标记替代关系，并在定期清理时归档或删除。
- 不为小实现选择新增 decision。
