## Principle

ASCII 框图内的内容必须使用 **英文**，禁止使用中文。

## Reason

- GitHub 等宽字体渲染中文字符宽度不一致（视觉占 2 倍，实际按 1 字符计算）
- 中文导致框图边框对齐问题，不同平台/字体显示错位
- 英文字符宽度统一，框图对齐稳定可靠

## Examples

```
✓ Correct (English):
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Architect                                         │
│  Responsibilities: Understand requirements, design solution, create plan    │
└─────────────────────────────────────────────────────────────────────────────┘

✗ Wrong (Chinese):
┌─────────────────────────────────────────────────────────────────────────────┐
│                           架构师                                            │
│  职责：理解需求、设计解决方案、创建可执行计划                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

## Alternatives

- 框图外的说明文字可使用中文
- 表格、列表中的内容可使用中文
- 仅在 ASCII 框图内部强制使用英文

## 常见问题与自动修复机制 (总结与经验)

在项目中编写或审查 Markdown 时，需要防范三种排版陷阱：
1. **中英文宽度不一致**（主要原因）：包含中文字符的行，长度计算经常在 GitHub 和本地终端不一致，破坏边框。
2. **多层嵌套框图未对齐**：外部大框和小框嵌套时（例如 `agent/architect.md` 中的方法论模型），仅按照最外框宽度修改，会导致内部线条不对齐。

### 自动化对齐脚本 `scripts/align_ascii.py`

在遇到排版严重错误时，请直接翻译含有中文的行。或者使用在 `scripts/` 下的对齐脚本：

```bash
# 自动修复文件里的 ASCII Diagram 对齐
python scripts/align_ascii.py agent/architect.md
```

执行后请使用 `git diff` 核对修改是否准确。
