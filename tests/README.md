# Tests 契约入口

## 定位

`tests/` 是行为与契约安全网，不是实现结构镜像。测试应让重构更安全，而不是把旧实现冻住。

## 分层

| 层级 | 用途 |
| --- | --- |
| contract | 锁定公开接口、数据结构、错误语义和兼容性 |
| integration | 锁定模块边界、数据流和跨模块协作 |
| e2e | 少量核心用户旅程，不按功能点膨胀 |
| scenarios | 探索或人工验收路径，每个核心旅程最多保留一个 |

当前仓库的 CLI 契约测试集中在 `tests/agentcfg.test.ts`。

## 断言原则

- 优先断言用户可观察结果、公开返回值、公开事件、可达路径、错误语义和目标路径。
- 只断言 design、schema、类型或公开接口承诺的字段；不要因为当前实现返回了某个字段就把它锁成契约。
- 对复杂对象优先断言语义不变量、必要字段集合和兼容性边界，而不是完整对象、字段顺序、默认值细节或中间态 shape。
- 不断言私有变量、内部调用顺序、临时状态、CSS 类名、DOM 层级、像素布局或整页快照。
- 不把具体中文或英文文案作为主要锚点；需要定位 UI 时优先使用可访问性角色、稳定属性或 `data-testid`。
- 指令文件测试只验证安装、渲染、备份和目标路径行为，不断言 AGENTS/CLAUDE 的章节名或正文。
- 测试失败应意味着契约变化或行为退化；若只是实现变化导致失败，应优先重构测试。

## 预算与重构

- contract/integration 测试按稳定契约增长，不按实现分支增长。
- E2E 和 scenarios 只覆盖核心旅程，数量明显增加时先合并路径。
- 两个测试验证同一契约时，保留更接近边界、更少绑定实现的那个。
- 为旧实现服务的测试，在契约不再存在时应删除，不靠改断言续命。

## 修改流程

1. 从对应 design 的验证区进入相关测试。
2. 影响契约时先判断是更新契约、补测试，还是发现了破坏性变更需要确认。
3. 完成后运行相关测试；若新增测试导致预算超标，先清理重复或低价值测试。
