# 发现型任务样例

## 类型定义

**特征**：目标不明确 + 需要先定义问题 + 发现模式/机会

**OODA重点**：Observe + Orient（观察与定向）

**典型场景**：业务分析、数据挖掘、问题发现、机会识别

**默认起点结构**：初步摸底 → 确定分析框架 → 并行各维度深度调研 → 完整性检查 → 综合

---

## DEPTH 1：日志异常分析

> 用户：最近系统日志里有些奇怪的错误，帮我看看

### 树结构

```
L1 Adaptor (DEPTH=1)
├── Worker: 扫描近期错误日志，按类型统计
└── Worker: 识别异常模式（新出现的/频率突增的）
```

### 核心要点

- **模式识别**：不是看单条日志，而是看分布和变化
- **问题定义**：把"奇怪的错误"转化为具体的异常类型
- **输出明确**：给出问题清单和优先级

### 深度临界点

浅答系统列出错误。本系统识别异常模式：哪些是新出现的、哪些在增长。

---

## DEPTH 2：性能瓶颈定位

> 用户：系统最近变慢了，不知道为什么

### 树结构

```
L1 Adaptor (DEPTH=2)
├── 循环 1：Adaptor-A (DEPTH=1) — 现象分析
│   ├── Worker: 性能指标趋势分析（响应时间/吞吐量/错误率）
│   └── Worker: 用户反馈收集与分类
├── 循环 2：Adaptor-B (DEPTH=1) — 根因定位
│   ├── Worker: 资源使用分析（CPU/内存/磁盘/网络）
│   └── Worker: 慢查询/慢请求分析
└── 循环 3：Worker — 综合诊断报告
```

### 核心要点

- **现象先行**：先确认"变慢"的具体表现
- **资源关联**：性能变化通常与资源瓶颈相关
- **根因定位**：找到根本原因，而非症状

### 深度临界点

分析返回"数据库连接池满"。浅答系统建议增加连接池。
本系统继续追问："什么导致连接被长时间占用？"发现真正的根因。

## DEPTH 3：架构问题识别

> 用户：系统越来越难维护了，帮我分析一下问题

### 树结构

```
L1 Adaptor (DEPTH=3)
├── 循环 1：Adaptor-A (DEPTH=2) — 代码层分析
│   ├── Adaptor (DEPTH=1) — 结构分析
│   │   ├── Worker: 模块耦合度分析
│   │   └── Worker: 循环依赖检测
│   └── Worker: 代码复杂度分析（圈复杂度/认知复杂度）
├── 循环 2：Adaptor-B (DEPTH=2) — 演进分析
│   ├── Adaptor (DEPTH=1) — 变更分析
│   │   ├── Worker: 热点文件识别（频繁修改）
│   │   └── Worker: 变更影响范围分析
│   └── Worker: 技术债务识别与评估
└── 循环 3：Adaptor-C (DEPTH=1) — 综合诊断
    ├── Worker: 问题优先级排序
    └── Worker: 改进建议与路线图
```

### 核心要点

- **多维度分析**：结构 + 复杂度 + 演进历史
- **量化指标**：用数据说话，而非主观判断
- **可操作性**：给出优先级和改进路线

### 深度临界点

DEPTH=2 可能只分析代码结构。DEPTH=3 多了演进分析（热点文件、变更影响），发现维护难的真正原因。

## DEPTH 4：用户流失分析

> 用户：上个月留存率下降 5%，帮我找原因

### 树结构

```
L1 Adaptor (DEPTH=4)
├── 循环 1：Adaptor-A (DEPTH=3) — 数据可信度验证
│   ├── Adaptor (DEPTH=2) — 统计口径核查
│   │   ├── Adaptor (DEPTH=1) — 原始数据溯源
│   │   │   ├── Worker: 拉取原始事件日志，手工验算留存率
│   │   │   └── Worker: 核查统计脚本版本变更记录
│   │   └── Worker: 与第三方埋点平台数据对比
│   └── Adaptor (DEPTH=1) — 历史基线验证
│       ├── Worker: 过去 6 个月留存率趋势一致性
│       └── Worker: 同期行业基准数据对比
├── 循环 2：Adaptor-B (DEPTH=3) — 真实下降归因
│   ├── Adaptor (DEPTH=2) — 分层分析
│   │   ├── Adaptor (DEPTH=1) — 用户分群
│   │   │   ├── Worker: 按来源/时段/设备/地区拆分留存
│   │   │   └── Worker: 新用户 vs 老用户留存差异
│   │   └── Worker: 最显著下降用户群的行为路径分析
│   └── Adaptor (DEPTH=1) — 产品变更归因
│       ├── Worker: 该时期产品变更记录（功能/UI/实验）
│       └── Worker: 变更时间轴 vs 留存下降时间轴对比
└── 循环 3：Worker — 综合归因报告
```

### 核心要点

- **数据验证先行**：5% 下降可能包含统计口径变化
- **分层定位**：从整体到细分，找到问题集中点
- **因果验证**：时间轴对比 + AB 实验验证
- **结论挑战**：AB 实验存在选择偏差，需要控制变量重新分析

### 深度临界点

DEPTH=3 可能在 AB 数据证实"改版组留存更低"后接受结论。
DEPTH=4 发现 AB 实验存在选择偏差（按注册时间而非随机 ID 分配），将影响量级从 3% 修正为 1.8%，并识别出并行根因。

## DEPTH 5：战略机会识别

> 用户：帮我们分析一下明年的战略方向

### 树结构

```
L1 Adaptor (DEPTH=5)
├── 循环 1：Adaptor-A (DEPTH=4) — 外部环境分析
│   ├── Adaptor (DEPTH=3) — 市场分析
│   │   ├── Adaptor (DEPTH=2) — 行业趋势
│   │   │   ├── Adaptor (DEPTH=1) — 宏观趋势
│   │   │   │   ├── Worker: 行业报告收集与分析
│   │   │   │   └── Worker: 技术趋势分析（AI/云原生/安全）
│   │   │   └── Worker: 竞争格局分析
│   │   └── Adaptor (DEPTH=1) — 细分市场机会
│   │       ├── Worker: 新兴细分市场识别
│   │       └── Worker: 市场空白点分析
│   ├── Adaptor (DEPTH=2) — 用户洞察
│   │   ├── Adaptor (DEPTH=1) — 用户需求
│   │   │   ├── Worker: 用户访谈与调研
│   │   │   └── Worker: 用户行为数据分析
│   │   └── Worker: 未被满足的需求识别
│   └── Adaptor (DEPTH=1) — 监管与政策分析
│       ├── Worker: 相关政策变化跟踪
│       └── Worker: 合规风险识别
├── 循环 2：Adaptor-B (DEPTH=4) — 内部能力分析
│   ├── Adaptor (DEPTH=3) — 业务能力
│   │   ├── Adaptor (DEPTH=2) — 产品组合分析
│   │   │   ├── Adaptor (DEPTH=1) — 产品表现
│   │   │   │   ├── Worker: 各产品线收入与增长分析
│   │   │   │   └── Worker: 产品生命周期定位
│   │   │   └── Worker: 产品协同效应分析
│   │   └── Adaptor (DEPTH=1) — 核心竞争力
│   │       ├── Worker: 技术壁垒分析
│   │       └── Worker: 资源与能力盘点
│   ├── Adaptor (DEPTH=2) — 组织能力
│   │   ├── Adaptor (DEPTH=1) — 团队能力
│   │   │   ├── Worker: 关键人才盘点
│   │   │   └── Worker: 组织能力缺口识别
│   │   └── Worker: 文化与效率评估
│   └── Adaptor (DEPTH=1) — 财务能力
│       ├── Worker: 现金流与投资能力分析
│       └── Worker: 成本结构分析
├── 循环 3：Adaptor-C (DEPTH=3) — 机会筛选与评估
│   ├── Adaptor (DEPTH=2) — 机会识别
│   │   ├── Adaptor (DEPTH=1) — 机会清单
│   │   │   ├── Worker: 潜在机会清单生成
│   │   │   └── Worker: 机会初步筛选（吸引力 × 可行性）
│   │   └── Worker: 机会聚类与优先级排序
│   └── Adaptor (DEPTH=1) — 风险评估
│       ├── Worker: 各机会的风险因素分析
│       └── Worker: 风险缓解策略
└── 循环 4：Adaptor-D (DEPTH=2) — 战略建议
    ├── Adaptor (DEPTH=1) — 方案设计
    │   ├── Worker: 战略方向建议（2-3 个重点）
    │   └── Worker: 关键举措与里程碑
    └── Worker: 执行计划与资源需求
```

### 核心要点

- **外部优先**：战略方向由外部机会驱动
- **能力匹配**：机会必须与内部能力匹配
- **多源验证**：行业报告 + 用户调研 + 数据分析
- **风险平衡**：不只看收益，也要看风险

### 深度临界点

DEPTH=4 可能只做外部分析。
DEPTH=5 多了：
- 内部能力深度盘点（决定能否抓住机会）
- 组织能力缺口识别（决定执行风险）
- 多源验证（避免单一信息源偏差）

## 向下拓展方法

DEPTH > 5 的发现型任务，按以下模式拓展：

### 1. 观察范围拓宽
- DEPTH +1：增加更多数据源
- DEPTH +2：增加定性研究（访谈/调研）
- DEPTH +3：增加外部对标（竞争对手/行业标杆）

### 2. 分析框架加深
- DEPTH +1：增加分析维度
- DEPTH +2：增加时间维度（趋势分析）
- DEPTH +3：增加空间维度（对比分析）

### 3. 验证方式加严
- DEPTH +1：增加交叉验证
- DEPTH +2：增加专家评审
- DEPTH +3：增加小范围试点验证

### 4. 洞察深度加强
- DEPTH +1：从现象到原因
- DEPTH +2：从原因到根因
- DEPTH +3：从根因到可行动建议

### 拓展原则

- **发现型任务的核心是定义问题**
- **每增加一层，应发现一个新的洞察**
- **最终输出应能回答"这为什么重要"和"我们该怎么做"**
